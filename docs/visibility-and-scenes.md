# 可见性、游戏场景与设置协议

## 设计边界

Clawd 采用保守、可解释的场景策略。Windows 没有通用可靠的“这是游戏”标记，因此程序不会猜测全部已安装游戏，也不会把所有全屏窗口都称为游戏。默认不会扫描应用列表；用户添加 EXE 后才匹配该应用。

场景探针只查询前台窗口 PID、可执行文件路径、所属显示器几何、左键按下状态，以及用户添加的游戏 EXE 是否仍在运行。它不读取窗口标题、屏幕像素、游戏内存或键盘文本，不要求管理员权限，不注入其他进程。

## 数据流

1. `WindowProbe.exe` 每 250 ms 读取前台窗口元数据与显示器边界。
2. 配置的游戏进程列表每秒扫描一次；仅检查用户添加的 EXE 名称，完整路径规则会在匹配时核对规范化后的完整路径。
3. 探针通过标准输出发送单行、版本化 JSON；设置规则通过标准输入下发，不通过命令行参数泄露路径。
4. `ForegroundAppMonitor` 限制消息大小、校验版本与字段、检测超过 3 秒的心跳中断，并以 1–30 秒退避重启。
5. `classifyScene` 生成可解释的场景和自动隐藏原因，`VisibilityController` 再与手动、锁屏和挂起原因合并。
6. 主进程只在最终可见状态变化时执行宠物窗口显示/隐藏，并把状态发送给设置页面。

## 隐藏模式

| 模式 | 已配置游戏在前台 | 游戏在后台运行 | 全屏应用 | 锁屏/挂起 |
| --- | --- | --- | --- | --- |
| 智能模式（默认） | 隐藏 | 不单独隐藏 | “全屏应用时隐藏”开启时隐藏 | 始终隐藏 |
| 游戏运行期间 | 隐藏 | 隐藏 | 不作为独立条件 | 始终隐藏 |
| 手动控制 | 不自动隐藏 | 不自动隐藏 | 不自动隐藏 | 始终隐藏 |

在智能模式下，用户添加的例外应用只会抑制当前前台窗口造成的游戏/全屏隐藏，不会清除用户手动隐藏、锁屏或系统挂起原因。游戏运行期间模式按用户明确选择的规则保持隐藏，即使前台切换到例外应用也不会显示。

## 防抖与原因优先级

- 锁屏与系统挂起立即隐藏。
- 手动隐藏持续有效，自动恢复不会清除它。
- 游戏/全屏进入需稳定 400 ms 后隐藏，以降低切屏闪烁。
- 离开自动隐藏场景后，按设置等待 500–5000 ms 再恢复，默认 900 ms。
- “收回当前屏幕”只修复位置，不清除任何隐藏原因。
- 显示原因作为集合保留；任意有效阻止原因存在时，普通恢复事件不能显示宠物。

## 本地设置

设置文件位于 `%APPDATA%\Clawd\settings.json`。旧版本没有 schemaVersion 的文件会按 v1 迁移，保留有效的造型、大小、巡游、动画、任务桥和位置设置。损坏 JSON 会先保留一份本地恢复副本，再回退到安全默认值。设置写入先写临时文件并替换目标文件；并发更改按队列合并。

主要新增字段：

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| `schemaVersion` | 设置结构版本 | `1` |
| `startVisible` | 启动时显示宠物；关闭后仍可从托盘显示 | `true` |
| `autoHideMode` | `smart`、`game-running` 或 `manual` | `smart` |
| `hideFullscreen` | 智能模式是否隐藏所有全屏应用 | `true` |
| `restoreDelayMs` | 退出自动隐藏场景后的等待时间 | `900` |
| `appRules` | 用户本地添加的游戏/例外 EXE 规则 | `[]` |

规则最多 48 条，传入探针的数据有 96 KiB 上限；重复 ID、非法字段和超出消息预算的规则会被忽略。完整路径是默认匹配方式；切换到文件名会匹配不同目录下同名程序，可能产生误匹配。

## 原生探针协议

每行一个 JSON 对象，`schemaVersion` 当前为 1。字段包括 `sequence`、Unix 毫秒 `timestamp`、`foregroundPid`、`foregroundName`、`foregroundPath`、`fullscreen`、`mouseDown` 和 `runningRuleIds`。Renderer 不接收原始探针输出；IPC 的来源限定为本应用窗口。

探针不可用时，桌宠仍可手动使用，但自动场景识别不可保证。若探针在游戏隐藏期间失败，会暂时保留最近一次有效的自动隐藏原因，避免因未知状态突然遮挡游戏；用户可以从设置切换为手动模式。探针恢复后会重新采样并更新状态。

## 版本检查与更新

设置中心“隐私与关于”页面的“检查新版本”按钮会按需请求 Clawd 独立边缘入口 `clawd-updates.chronokalamos.com`；边缘入口不可用时，应用回退到 GitHub 公开 latest-release API。两者只读取 `LYL-Z/clawd-desktop` 的最新正式版，不包含草稿和预发布版本；应用使用 SemVer 比较本机版本与 Release tag。[GitHub 官方 API 文档](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)

版本检查不会自动运行或下载程序。发现新版本后，用户可以选择在设置页下载，或打开固定的 GitHub Release 页面。下载器将 EXE 写入 `%APPDATA%\Clawd\updates\<version>`，优先请求 Clawd 边缘下载入口，失败时回退至 GitHub；支持 HTTP Range 续传和取消后保留 `.part` 文件。完整下载后需同时通过字节长度和 Release `SHA256SUMS.txt` 中的 SHA-256 校验，校验通过才显示“打开文件位置”。portable EXE 不会自动安装或替换自身，用户需关闭 Clawd 后手动运行新文件。

请求只发送固定服务地址、应用版本化 User-Agent、HTTP Range 和 GitHub 所需请求头；不会附带设置、应用规则或个人路径。网络服务仍会接收到正常 HTTPS 请求元数据，例如来源 IP。没有网络、未发布正式 Release、GitHub 公共请求受限或 Worker 配额不足时，应用给出本地提示并保持现有版本可用。普通全球边缘网络可改善部分连接，不代表中国大陆全部运营商/线路始终可达；中国境内网络覆盖仍须按设备和运营商实测。
